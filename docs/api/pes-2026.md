# Integrasi monitoring PES SE2026

Portal publik: `/se/2026/pes`. Data PES terpisah dari Fasih SE2026 utama.
Scraper sumber **belum disertakan**. Halaman tidak menampilkan angka contoh jika
belum menerima data. Tiga tabel harus dimigrasikan sebelum rilis; lihat
`npm run db:migrate-pes` dan panduan deployment.

## Pengiriman scraper

`POST /api/se/2026/external/pes`

Header:

```http
Authorization: Bearer <token-SE2026-dengan-scope-write:pes>
Content-Type: application/json
```

Token dibuat melalui dashboard API SE2026 dengan scope `write:pes`. Scope
`write:progress` saja ditolak. Scope `admin` tetap mengikuti aturan guard yang
sudah ada. Jangan menaruh token pada URL, browser publik, source, atau log.
Pembatasan yang diwarisi adalah 60 request per menit per token **per proses**;
bucket dibagi dengan endpoint lain yang memakai token sama. Ini bukan limiter
terdistribusi antar-replika.

Contoh JSON (data ilustrasi kontrak, bukan data portal):

```json
{
  "snapshot_ts": "2026-11-05T09:30:00+07:00",
  "petugas": [
    {
      "pencacah": "pes-user-001",
      "nama_ppl": "Petugas Contoh",
      "nama_pml": "Pengawas Contoh",
      "total": 20,
      "open": 2,
      "draft": 3,
      "submitted_pencacah": 4,
      "submitted_responden": 0,
      "approved": 8,
      "rejected": 1,
      "revoked": 0,
      "completed_admin": 1,
      "edited_admin": 0,
      "edited_pengawas": 1,
      "selesai_cacah": 14,
      "selesai_approve": 9
    }
  ]
}
```

| Kolom | Aturan |
| --- | --- |
| `snapshot_ts` | Waktu kondisi sumber ISO 8601 dengan zona (`Z` atau offset); wajib, maksimal 5 menit di masa depan. Bukan waktu retry. |
| `pencacah` | Kunci sumber stabil dan peka huruf besar/kecil, 1–150 karakter setelah trim. Boleh berupa ID/email sumber, selalu privat. Nama bukan kunci. |
| `nama_ppl` | Nama tampilan publik wajib, 1–150 karakter, tidak boleh email. |
| `nama_pml` | Nama pengawas publik, maksimal 150 karakter; boleh kosong/diabaikan. Tidak boleh email. |
| `total` | Assignment terkini petugas, wajib; denominator persentase. |
| Status `open` sampai `edited_pengawas` | Angka kumulatif kondisi terkini; jika diabaikan menjadi 0. Kirim seluruh status agar tidak menghapus status lama tanpa sengaja. |
| `selesai_cacah`, `selesai_approve` | Wajib; rekap selesai menurut aturan sistem sumber. Server tidak menebak dari penjumlahan status. Pemeriksaan tidak boleh melebihi pendataan. |

Seluruh angka harus bilangan bulat JSON nonnegatif, maksimal 2.147.483.647, dan
masing-masing tidak boleh melebihi `total`. Target nol sah jika semua angka nol.
Jangan kirim string angka, persentase, kode wilayah, atau kolom tambahan. Maksimal
6.000 petugas unik per kiriman dan **4 MiB body aktual**, tanpa Content-Encoding.
Tabel menampilkan Submitted sebagai jumlah kedua kolom submitted; Approved/Final
sebagai `selesai_approve`. Rincian status asli tetap tersedia melalui API.

Setiap baris adalah **penggantian kondisi lengkap**, bukan penambahan angka.
Petugas yang tidak dikirim tidak berubah. Assignment berpindah harus mengirim
kondisi baru kedua petugas dalam satu kiriman. Untuk menonaktifkan assignment
petugas, kirim seluruh angka nol; tidak ada penghapusan implisit. Nama sama dengan
ID berbeda tetap dua petugas. Pertahankan kunci sumber saat nama berubah.

Seluruh metadata, kondisi, dan riwayat satu kiriman berada dalam transaksi.
Replay identik (waktu dan isi sama, urutan petugas boleh berubah) tidak menggandakan
snapshot atau riwayat. Snapshot yang lebih tua untuk salah satu petugas menolak
**seluruh kiriman**. Waktu sama dengan isi berbeda juga konflik. Gunakan timestamp
sumber baru untuk koreksi; jangan memalsukan waktu baru hanya untuk melewati konflik.

Respons berhasil:

```json
{"ok":true,"snapshot_id":42,"duplicate":false,"updated":1}
```

Replay mengembalikan `duplicate:true`, `updated:0`, dan ID snapshot yang sama.
Baris dengan timestamp dan isi sama dapat dilewati pada kiriman parsial baru.

| HTTP | Arti / tindak lanjut |
| --- | --- |
| 400 | JSON/skema/timestamp tidak valid; perbaiki payload. Respons validasi mempunyai `issues` berisi path dan pesan, tanpa nilai privat. |
| 401 | Token kosong, salah, kedaluwarsa atau dicabut. |
| 403 | Token bukan SE2026 atau scope tidak cukup. |
| 409 | Waktu terlambat atau waktu sama dengan isi berbeda; transaksi dibatalkan. Ambil kondisi sumber terbaru. |
| 413 | Body lebih dari 4 MiB. Bagi kiriman sesuai kelompok assignment yang harus atomik. |
| 415 | Content-Type/Content-Encoding tidak didukung. |
| 429 | Kuota token per menit habis; tunggu dan retry kiriman yang sama. |
| 500/503 | Guard/database belum tersedia; retry dengan backoff dan payload/timestamp yang sama. Respons bisa hilang setelah commit; retry identik tetap aman. |

Audit memakai `api_audit_log` yang sudah ada (token ID, path, status, durasi,
metadata request), tanpa token mentah atau isi rekap. Guard dan audit mengikuti
perilaku integrasi lama; audit bukan jaminan penyimpanan jika DB audit sendiri gagal.

Contoh pengiriman dari lingkungan scraper:

```bash
curl --fail-with-body -X POST \
  https://sensus.bpskabmusirawas.com/api/se/2026/external/pes \
  -H "Authorization: Bearer $PES_API_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @pes-snapshot.json
```

## Rekap dan riwayat publik

`GET /api/se/2026/public/pes?from=2026-11-01&to=2026-11-05`

Parameter opsional: `q` (substring nama, maksimal 150 karakter), `pengawas` (nama
pengawas persis, maksimal 150), `petugas` (UUID publik), `from` dan `to` (tanggal
WIB, inklusif). Filter digabung dengan AND dan berlaku pada `summary`, `petugas`,
`history`, serta `latest_source_at`. `options` selalu berisi pilihan roster terkini
agar filter dapat diganti. Default 14 hari sampai hari ini WIB; maksimal 90 hari,
tidak boleh melebihi hari ini. Rentang ini tidak membatasi rekap kondisi terkini.

Respons 200 berisi:

- `petugas`: UUID publik, nama, nama pengawas, seluruh counter, `observed_at` UTC,
  `pct_cacah`, `pct_approve` (persen satu desimal, target nol menghasilkan 0).
- `summary`: `petugas`, `total`, `selesai_cacah`, `selesai_approve`, `sisa`,
  `pct_cacah`, `pct_approve`. Persen total berbobot assignment, bukan rata-rata persen.
- `options`: UUID/nama/pengawas untuk pilihan filter; tidak berisi kunci sumber.
- `range`: `from`, `to`; `history`: satu titik per tanggal, termasuk hari kosong.
- `latest_source_at`: timestamp sumber terbaru pada hasil filter, atau null.

Riwayat menyimpan kondisi terakhir setiap tanggal **Asia/Jakarta** per petugas,
termasuk target pada tanggal itu. Target baru tidak menulis ulang hari sebelumnya.
Titik berisi `tanggal`, `total`, `selesai_cacah`, `selesai_approve`,
`delta_cacah`, `delta_approve`, `updated_count`, `baseline_count`, `spans_gap`.
Target dan capaian sebelum data pertama bernilai null. Hari tanpa kiriman membawa
kumulatif terakhir dengan `updated_count:0` dan delta null. Snapshot pertama
petugas menjadi baseline, bukan tambahan harian; bila hari itu memuat baseline baru,
delta agregat sengaja null karena belum seluruh perubahan dapat dibandingkan.
Setelah jeda, delta dibandingkan snapshot terakhir yang tersedia dan
`spans_gap:true`. Koreksi/perpindahan dapat menghasilkan delta negatif. Persentase
historis dihitung dari capaian dan target pada titik yang sama, bukan target hari ini.

Riwayat yang difilter pengawas menggunakan keanggotaan petugas **terkini**. Tidak
ada histori struktur pengawasan. Petugas yang belum pernah dikirim pada tanggal
tertentu belum ikut total tanggal itu; total historis bukan estimasi sampel penuh.

Tidak ada email/kunci sumber, token, atau informasi responden di respons publik.
Database kosong menghasilkan array kosong dan source null; antarmuka menampilkan
status menunggu data, bukan angka contoh. Parameter tidak valid menghasilkan 400.
Tabel belum dimigrasikan/DB gagal menghasilkan 503 dengan `code:PES_UNAVAILABLE`;
detail SQL tidak dikirim. Respons tidak di-cache. Halaman melakukan polling 60
detik hanya saat tab aktif dan refresh saat kembali ke tab; data terakhir yang
sempat dimuat diberi pesan jika refresh gagal.

## Pengujian lokal dengan database sementara

```bash
docker run -d --name simonsen-pes-test -p 127.0.0.1::3306 \
  -e MYSQL_ALLOW_EMPTY_PASSWORD=yes -e MYSQL_ROOT_HOST=% \
  -e MYSQL_DATABASE=simonsen_pes_test mysql:8.4
docker port simonsen-pes-test 3306
# Set PES_TEST_MYSQL_PORT ke port loopback yang tampil, lalu:
npm run test:pes:mysql
```

Tes MySQL hanya memakai nama DB `simonsen_pes_test`, loopback dan port eksplisit;
tidak membaca .env aplikasi. Jangan arahkan pengujian ke database produksi.
